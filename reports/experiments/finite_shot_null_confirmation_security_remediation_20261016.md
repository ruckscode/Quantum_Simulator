# Finite-shot null-confirmation security remediation

**Decision: BLOCK EXTERNAL TRUST PROVISIONING.** Several code-level checks have been strengthened, but external trust cannot be established locally, code verification is not tied atomically to the already imported executable objects, and the frozen generic sampler remains directly callable. No reviewer credentials were provisioned and no confirmation samples were generated.

## Original adversarial findings

| Original finding | Status | Remediation and remaining evidence |
|---|---|---|
| 1. Trust-anchor substitution | **BLOCKER** | The production trust paths remain fixed under `C:\ProgramData\QuantumSimulator\finite-shot-null-confirmation` (`experiments/finite_shot_null_confirmation.py:42–47`), and execution exposes no trust-path argument (`:456–479, 547–557`). Trust records now reject symlinks/reparse points (`:_assert_directory_no_reparse`, `:275–283`), and a trust-root ID is included in the signed manifest. But no code checks effective Windows ACLs or that the execution identity cannot replace the trust files. This workspace cannot establish administrator ownership or ACLs; the production root is currently inaccessible/missing and verification fails closed. **External prerequisite:** an administrator must provision and verify the ACL and identity mapping outside the execution account. Do not mark the trust root independent based on the JSON boolean. |
| 2. Manifest substitution | **PASS for the supported execution API; residual in-process risk** | `execute_confirmation` accepts only fixed preregistration, binding, and output paths and has no expected-manifest/hash or trust-path arguments (`:456–479`). It computes the manifest from current files, configuration, runtime, and seed ledger (`artifact_manifest`, `:237–267`); the signed manifest must equal it (`verify_signed_approval`, `:322–324`). The approval binds the experiment ID, trust-root ID, reviewer/key IDs, and a UUIDv4 run ID. A Python caller able to mutate module globals or monkeypatch functions is outside what this in-process API can prevent; the remaining protected-launcher requirement below addresses that boundary. |
| 3. Incomplete coverage / imported-code mismatch | **BLOCKER** | Added `verify_loaded_code_origins()` (`:223–235`) to require the imported `pair_outcome` and `compare_distributions` origins and module identities to match the pinned source locations. The artifact manifest now includes experiment ID, Python executable path, implementation, isolated-mode flag, platform, and dependency version strings (`:237–267`). Tests exercise a shadowed sampler object (`tests/test_finite_shot_null_confirmation.py:test_shadowed_loaded_sampler_or_detector_is_rejected`). These checks do not hash the actual interpreter or NumPy/cryptography binaries, validate all import hooks/startup modules, or compare loaded bytecode with the exact bytes hashed from disk. A version string and `co_filename` are not an execution identity proof. |
| 4. Path, symlink, and TOCTOU attacks | **BLOCKER** | `sha256_file` now rejects non-regular files and symlink/reparse components; strict JSON reads use the same path checks (`_assert_regular_no_reparse`, `strict_json_file`, `:74–120`). Execution checks the output parent and fixed paths (`:456–468`). A symlink test is present (`tests/test_finite_shot_null_confirmation.py:test_symlinked_trust_record_is_rejected_when_platform_supports_symlinks`), but it was skipped because this Windows environment did not permit creating the symlink. Hashing still performs a separate `lstat` and `read_bytes`, inputs are parsed and hashed in separate operations, and the driver/helper are imported before verification (`:20–32`). No immutable verified snapshot or OS-protected launch stage closes those races. |
| 5. Approval replay | **PASS for replay after recorded consumption; conditional on trust-root integrity** | Approval must contain a canonical UUIDv4 run ID signed together with the experiment, artifact manifest, and trust-root identity (`verify_signed_approval`, `:292–324`). `consume_approval_run` creates a marker exclusively before sampling (`:338–353, 482`); verifier rejects a marker already present. The interruption test stops at preflight before any RNG call and confirms the same approval cannot resume (`tests/test_finite_shot_null_confirmation.py:test_interrupted_preflight_consumes_authorization_and_cannot_resume`). Marker durability and non-removability still depend on the unverified ProgramData ACL. A crash after consumption intentionally loses the run; no resume or new independent sample is claimed. |
| 6. Signature, identity, duplicate JSON | **PASS for signature mechanics and duplicate-key rejection; UNRESOLVED for human identity** | Trust and approval JSON now use `object_pairs_hook=_unique_object`, which rejects duplicate keys (`:110–120, 275–283`). The signature covers canonicalized parsed approval fields except the signature itself, and verification checks key ID, reviewer ID, trust-root ID, UUIDv4, manifest equality, and Ed25519 signature (`:292–335`). Tests cover duplicate approval fields, altered signatures, key mismatch, and stale manifests. A valid signature proves possession of the configured private key; this code cannot prove that the key belongs to an independent human. The administrator’s out-of-band identity/independence verification remains an external prerequisite. |
| 7. Fail-closed behavior | **PASS for missing, inaccessible, malformed, and mismatched records; UNRESOLVED for ACL integrity** | Missing trust directories/files and read errors now raise before sampling; malformed or duplicate JSON and mismatched signatures/manifests reject (`:74–120, 275–335`). The production trust check was run and failed closed because `C:\ProgramData\QuantumSimulator` is unavailable. Failure to verify the trust root’s ACL remains the first blocker. |
| 8. Alternate sampling entry points | **BLOCKER** | The confirmation loop still calls imported `pair_outcome` (`finite_shot_null_confirmation.py:512`), while the existing public helper draws multinomial counts directly (`experiments/finite_shot_synthetic_characterization.py:52–56`) and the original runner calls it (`:124–149`). The adversarial test replaces `default_rng` with a sentinel and proves that calling `pair_outcome` with the registered confirmation condition reaches the RNG without authorization, while generating no sample (`tests/test_finite_shot_null_confirmation.py:test_public_pair_helper_reaches_rng_without_confirmation_authorization`). I left the frozen runner untouched because its source hash is registered in the original experiment. **Correction requires a separately versioned sampler/runner plus an execution identity or protected launcher that cannot call the old helper.** Moving the code into another callable module would not close the bypass. |
| 9. Interrupted execution and seed reuse | **PASS for same-approval retry rejection; UNRESOLVED for deployment tampering** | The signed run ID is consumed before seed preflight or any pair (`:482–486`), and cannot be consumed twice (`:338–353`). If execution is interrupted, the marker prevents resume; the existing deterministic seed ledger remains unchanged. This deliberately sacrifices recoverability rather than treating repeated deterministic streams as independent. If an actor can delete the marker, that is the trust-root ACL blocker. |

## Tests and validation

Focused authorization/adversarial command:

`.venv\Scripts\python.exe -m pytest tests/test_finite_shot_null_confirmation.py -q --tb=short --basetemp .pytest-remediation-focused-20261015-l`

Result: **14 passed, 1 skipped**. The skip is the symlink-creation test because this environment does not permit creating symlinks. The public-helper bypass test intercepts the first RNG request with a sentinel; it does not generate counts. The interruption test raises at resource preflight after consuming the authorization and before the sampling loop.

Lightweight checks passed: strict JSON parsing of the registered preregistration and local binding; local driver/reference/statistics source bindings and loaded-origin checks; deterministic seed-ledger digest `222e5522204fd09f56f860c4a474130b2357d34997c9393f0d47521953f341ad`; designated confirmation result file absent; production trust gate fails closed because the external root is unavailable. `git diff --check` passed with existing LF/CRLF warnings on unrelated working-tree files.

## Remaining prerequisites

1. An administrator must create the fixed external trust root, verify effective ACLs deny write/delete rights to the execution identity (including inherited/group rights), and authenticate the reviewer public key and identity outside the workspace.
2. Use a protected launcher and immutable staged runtime that verifies source/dependency bytes before import and executes only the verified modules. The current Python module cannot close its own import-time and in-process mutation races.
3. Keep the generic public sampler inaccessible to the confirmation execution identity, or introduce a separately registered sampler whose only entry point is the protected launcher. Do not alter the original experiment’s pinned helper as part of this remediation.
4. Retain the one-time consumed-run marker in the protected trust store. A consumed/aborted run cannot resume; any new independent run requires a separately approved design and non-overlapping seed policy.

The scientific registration is unchanged: 38,228 pairs, 1,024 shots, same null distributions, detector threshold, one-sided 5% Clopper–Pearson rule, and 2,217-flag boundary. No production trust key, reviewer identity, or approval was created.
