# Independent pre-execution review: finite-shot null confirmation

**Review date:** 2026-10-15 (review of the prospective 2026-10-16 design)  
**Scope:** Static code, configuration, and integrity review only. No confirmation samples were generated and `execute_confirmation` was not invoked.

## Decision

**BLOCK EXECUTION.** The detector path, registered workload, and primary statistical rule are consistent. The current binding explicitly says review is pending, so the driver correctly refuses to proceed today. However, its future “review release” check authenticates only a mutable status field and the bytes of a workspace file; it does not establish an independent reviewer or authenticate that reviewer’s release. The external hash arguments likewise have no enforced trust anchor. Before execution, require a trusted, independently authenticated release bound to the exact preregistration, driver, and local binding digests, and use independently obtained caller pins. No code or binding changes are proposed as part of this audit.

| **PASS, conditional on the registered pseudorandom IID model** | **The deterministic seed ledger is repeatable and has no detected reuse in the registered ledger.** Seeds are derived from protocol, shots, condition, replicate, and role using SHA-256 truncated to 32 bits (`finite_shot_synthetic_characterization.py:45–49`). The driver derives both role seeds for all replicates, verifies the ordered digest and all-seed uniqueness, and compares against the prior 1,024-shot streams (`finite_shot_null_confirmation.py:190–223`). The binding records 76,456 unique streams and zero prior overlap (`driver_binding…json:14–19`), and tests recompute the ledger twice without sampling (`tests/test_finite_shot_null_confirmation.py:79–87`). This supports deterministic non-overlap for this fixed ledger. It does not prove mathematical independence: the preregistration itself identifies IID flags and adequate pseudorandom independence as assumptions (`preregistration…json:72–77`). |

Thus the present record blocks execution. But `_check_review_release` accepts any workspace file whose digest matches a caller-editable binding field after the status is changed to `reviewed_and_released` (`:242–250`). It does not inspect review content, reviewer identity, reviewer independence, scope, or an authenticated signature. The implementation report correctly describes the check as file integrity only (`finite_shot_null_confirmation_implementation_20261016.md:19`). `test_pending_independent_review_blocks_sampling` tests only the pending state (`tests/test_finite_shot_null_confirmation.py:123–126`), not forged or unauthenticated release. This is insufficient for the preregistered requirement that the driver be independently reviewed before sampling (`preregistration…json:17, 40`). |
| **BLOCKER** | **The caller-pinned hash requirement has no enforced external trust anchor.** `verify_hash_bindings` correctly compares caller-supplied driver and binding digests against current files, and validates preregistration, detector/reference-source, configuration, and seed-ledger bindings (`finite_shot_null_confirmation.py:128–162`). The tests pass self-computed file hashes (`tests/test_finite_shot_null_confirmation.py:17–24`), which tests consistency but not independent pin provenance. Execution requires pins obtained through a trusted review/release channel. |
| **UNRESOLVED** | **Behavior-affecting runtime dependencies are version-checked but not content-pinned.** The registered source hashes cover the driver, reference runner (including `pair_outcome`, seed derivation, and CP helpers), and `statistics.py`; local comparisons pass. The driver checks Python and NumPy version strings and records the `default_rng` bit-generator description (`finite_shot_null_confirmation.py:304–306, 347–359`), while the preregistration requires those runtime fields (`preregistration…json:56–69`). It does not hash the installed NumPy package/wheel or other runtime implementation. Whether version pinning alone is sufficient for the intended reproducibility standard is not established by these artifacts. The exact execution environment and package provenance must be retained in the eventual run record. |
| **UNRESOLVED** | **Independence is a model assumption, not verified by distinct seeds.** Separate seeds and zero collisions/overlap are verified for the fixed streams, but 32-bit seed uniqueness does not prove independent PRNG output or IID Bernoulli flags. This limitation is explicitly acknowledged in the preregistration (`:35–39, 72–77`). The exact-binomial power and confidence interpretation is valid conditional on the stated IID model. No evidence in this review establishes independence beyond the documented pseudorandom procedure. |
| **PASS with operational limitation** | **The explicit execute flag and current pending gate stop the present invocation before sampling.** `execute_confirmation` raises unless `execute_sampling=True` (`finite_shot_null_confirmation.py:279–290`), then validates fixed paths, absence of an existing output, hashes, and release status before the sampling loop (`:291–327`). A rerun with the same ledger and compatible runtime would repeat the same deterministic streams, but execution records should distinguish aborted attempts from completed runs. |

## Source and integrity checks performed

- Parsed the preregistration and binding as JSON and recomputed their referenced local SHA-256 values. All present local binding comparisons match; the review-release record remains pending.
- Traced the called detector and statistical helper code without calling `pair_outcome`, generating multinomial draws, or invoking the confirmation driver.
- Confirmed the designated confirmation-results file does not exist.
- Existing tests provide unit coverage for workload/cap checks, hash mismatch rejection, decision boundary, deterministic ledger derivation, explicit flag, and pending review. They do not certify review identity or independent caller-pin provenance.

## Smallest required correction before execution

Keep the experiment design and detector fixed. Obtain an independent review artifact that identifies the reviewer, establishes the required independence, states the review scope and release decision, and is authenticated through a trusted mechanism. Bind that release to the exact preregistration, driver, binding, and dependency/runtime identifiers, and require the invocation’s expected digests to come from that trusted source. Then repeat a static integrity check on the final frozen files before any sampling. This review does not supply that release or authorize execution.
