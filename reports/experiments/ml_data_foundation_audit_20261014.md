## Feature and leakage audit

The current candidate feature definitions are in `ml_evaluation.py`; the production schema is the first five observable fields in `ml_training.PRODUCTION_OBSERVABLES`.

| Feature(s) | Source and integrity finding |
| --- | --- |
| `total_variation_distance`, `js_divergence`, `hellinger_distance` | Derived from ideal/reference and observed execution distributions. They are outcome-time measurements, not identifiers or diagnosis outputs, but here both distributions are produced by this simulator and scenario construction. They do not constitute independent truth. |
| `observed_entropy_bits`, `observed_max_probability` | Derived from observed counts (all 270 rows have finite values). These are legitimate observation summaries for a future prediction task, subject to source-compatible, family-lineage-separated validation. |
| `calibration_readout_error_max`, `calibration_t1_min`, `calibration_t2_min` | Extracted from the configured hardware profile, not independently acquired calibration measurements. In this data construction the NORMAL and PROGRAM_FAULT rows use the healthy profile while HARDWARE_ANOMALY rows receive varied profiles. This is a synthetic condition shortcut / post-intervention configuration proxy; these three fields stay outside production predictors. |
| `gate_mismatch_fraction` | Directly compares reference and observed operation lists. In this data all 90 PROGRAM_FAULT rows are nonzero and all 180 NORMAL/HARDWARE_ANOMALY rows are zero. This directly reveals the injected program-change label. It remains only an explicitly named confounded ablation, never a blind-cause feature. |
| Labels, IDs, mutation/component descriptions, diagnosis fields | Explicitly excluded from the feature matrix, including the new `circuit_lineage_id`; lineage is a split key only and cannot be a predictor. `ground_truth_label` is assigned by controlled scenario construction in `ExperimentConfig`, so these labels are synthetic, not independent adjudications. |

Exact duplicate report fingerprints: 0/270; run IDs are unique; there are 30 base circuit IDs. A deterministic exploratory comparison of the 435 reference-circuit pairs found zero identical full operation sequences and 51 pairs with `difflib.SequenceMatcher` similarity at least 0.8 (maximum 0.962). That 0.8 screen is descriptive, not a pre-registered equivalence threshold. More directly, the generator uses a six-recipe cycle: families at indices separated by six share the same deterministic recipe slot while varying parameters/seeds. Family-only CV could therefore separate closely related recipe siblings. The current generator now records `circuit_lineage_id=design_recipe_01..06`; new split generation and validation group on this root, and reject a fold where a lineage appears on both sides. The old rows have no lineage key and are deliberately ineligible. Broader semantic/near-equivalence adjudication across external circuits remains required before any external claim.

## Prospective evaluation protocol (design only; no evaluation launched)

1. Before collection, freeze the sampling frame, source commit/environment, family/recipe lineage graph, inclusion rules, independent labels, feature schema, estimators, calibration method, metrics, target use and resource/power plan. All mutants, parameter variants, repetitions, and conditions descended from a common circuit recipe stay in one lineage root.
2. Assign complete lineage roots to three disjoint sets: **training/development**, **probability calibration**, and **untouched test**. Tune model structure and hyperparameters only with nested lineage-grouped validation inside development. Fit the selected calibrator only on the separate calibration set after the model is locked. Do not inspect test features/labels or test metrics until model and calibrator are frozen; use the test once.
3. Report a confusion matrix and class-wise precision, recall/sensitivity, specificity, and F1; macro-F1 and balanced accuracy; multiclass Brier score and log loss; calibration reliability plot plus calibration intercept/slope (ECE may be descriptive with binning declared); and abstention coverage/risk if abstention is used. Give 95% uncertainty intervals using bootstrap resampling of independent lineage roots, not individual rows. Preserve per-class support and failures.
4. Acceptance requires: complete provenance and independent labels; no duplicate or lineage crossing; training-only preprocessing; calibration-only calibrator fit; exactly-once sealed-test scoring; all classes represented with pre-powered independent roots; and complete class-wise/calibration metrics with root-cluster uncertainty. Before any new result is examined, an independent protocol review must freeze target-specific minimum performance and calibration requirements, maximum tolerable class-wise errors, and a minimum-information/power or interval-width requirement. No numeric utility thresholds are evidenced for this use case today, so performance pass/fail criteria are **not yet authorized or defined**. The existing frozen diagnosis acceptance criteria remain unchanged.
5. The current synthetic set has only six recipe lineages, synthetic labels, and no valid source provenance. It cannot support a defensible train/calibration/test evaluation or power claim. No ML evaluation/training was run in this phase.

## Independent truth and data disposition

The 270 local rows may be retained as synthetic simulator process-control examples with their construction labels. Independent adjudication is mandatory before using them to support real diagnosis accuracy, independent generalization, or benchmark claims. A blinded reviewer can separately verify that each configuration actually applied the declared mutation or hardware profile, but that checks simulator construction, not real-world truth. External QMutBench/Bugs4Q records without independent diagnosis categories/localization need benchmark authorship evidence or independent adjudication by reviewers blinded to model output; mutation operators alone do not establish the simulator's fault-diagnosis ground truth. No independent adjudication is present in the current set.
