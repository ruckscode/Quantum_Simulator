# Research gap and novelty assessment

**Prepared:** 2026-10-13  
**Status:** Read-only assessment and proposed study; no new simulation, training, threshold change, or hardware run was performed.

## Proposed paper and research question

**Working title:** *When Should a Quantum Program Diagnoser Abstain? Evidence-Calibrated Fault Diagnosis under Finite Shots*

**Research question:** Can a quantum-program diagnosis method distinguish statistically ordinary finite-shot fluctuations from anomalous output, and then assign a fault cause and location only when the observed evidence supports that level of specificity, while controlling false alarms and reporting its shot and compute costs on unseen circuit families?

This is a conditional direction, not a novelty claim established by the present artifacts. Existing work already covers quantum program statistical testing, mutation testing, fault localization, and quantum-circuit diagnosis. The strongest possible distinction is an experimentally validated *selective* diagnosis contract: separately calibrated anomaly evidence, cause evidence, and localization evidence, with abstention and risk-coverage reporting under family-held-out finite-shot evaluation. A shot-aware cutoff by itself is not a defensible primary contribution.

## Audit of the actual project

### Implemented behavior

| Capability | What the code actually does | Evidence and limitation |
|---|---|---|
| Output-distribution comparison | `src/quantum_simulator/statistics.py` computes TVD and flags when it exceeds `max(configured_threshold, 1/sqrt(shots))`. | This is a heuristic cutoff; it does not provide a calibrated null p-value or control a stated family-wise/type-I error rate. The permutation detector is empirical pooled-label permutation with a +1 correction and 999 resamples in the finite-shot calibration implementation. |
| Diagnosis category | `src/quantum_simulator/diagnosis_engine.py` applies deterministic evidence/rule selection. | Focused tests establish code behavior on constructed inputs, not calibrated diagnostic probabilities. |
| Program fault localization | `src/quantum_simulator/fault_localizer.py` compares operation lists and uses ideal-simulation traces to rank candidates. | Trace deviation alone is not treated as proof of a program fault. Candidate scores are heuristic rather than calibrated posterior probabilities or a mutation-spectrum ranking. |
| Hardware fault localization | `src/quantum_simulator/hardware_fault_localizer.py` uses calibration metadata and circuit relevance to rank candidate qubits/gates. | Evidence ranking is not a validated probabilistic localization model. Simulator metadata does not establish physical-device localization performance. |
| Simulated hardware effects | The local simulator implements selected readout and gate-skip effects and T1/T2-related paths. | Phase 5 audit documents that gate error is implemented as operation skip probability; the simulator is not a general hardware noise model and does not establish real-device validity. |
| ML adapter | The observable adapter uses five scalar features (TVD, Jensen–Shannon, Hellinger, observed entropy, and maximum probability); the logistic model has a 0.60 decision cutoff and explicitly uncalibrated probabilities. | A low-confidence abstention path exists, but the cutoff is not a demonstrated risk-control guarantee. The adapter continues to use the evidence localizer. |

### Evidence actually completed

* **Finite-shot calibration:** 3,600 valid configurations, all registered target decisions reproducible, 30/60 acceptance targets passed. The saved follow-up reports excessive TVD false positives at low shots, the permutation detector's sensitivity trade-off, and fixes 36 one-sided sensitivity lower-bound calculations. The repaired bounds are reporting corrections; they do not change original outputs or acceptance criteria. Calibration and its validation split are not a new held-out evaluation for a future candidate chosen from those data.
* **Exploratory shot-aware TVD:** calibration-derived q95 cutoffs were evaluated against the existing validation split. The follow-up reports subtle-fault detection of 13/120 at 256 shots, 41/120 at 1,024, and 109/120 at 4,096 for the validation split. This is useful candidate-selection evidence, not independent confirmation; its poor low-shot sensitivity argues against presenting q95 TVD as a solved detector.
* **Controlled fault localization Phase 1 / 1.4:** Phase 1.4 has 45 constructed runs from one two-qubit circuit family repeated over five seeds; reported 45/45 class accuracy, 0 false alarms, and 30/30 target localizations. This is within-family evidence, not broad generalization.
* **Independent Generalization Phase 2:** 36 constructed cases (12 scenarios × 3 seeds) across six circuit families, at 512 shots; reported class accuracy .917, macro-F1 .922, 22/30 positive detections, 0/6 control false positives, and localization 24 correct, 0 incorrect, 3 not justified, 7 abstentions. All three detection/localization misses are concentrated in `phase2_cx_q1_q3_readout`. The number of families and seeds is small, and scenario-derived labels do not establish external validity. The Phase 2 report itself notes that several strength variants share a family.
* **QMutBench pilot / Bugs4Q:** the saved QMutBench pilot has 12 cases, including one unsupported case, but no reliable independent ground-truth labels; its apparent program-fault decisions cannot support accuracy. The Bugs4Q validation report records no dataset and no benchmark results. Eight focused source cases likewise do not constitute an independent scored benchmark.
* **ML evidence:** `data/qmutbench_ml/final/grouped_model_comparison.md` reports leave-one-family-out evaluation on 270 prepared records from 30 families (tuned logistic regression accuracy .585, macro-F1 .576). This is modest classification evidence on that curated dataset, not performance of the current deployed artifact. The artifact `src/quantum_simulator/models/observable_logistic_regression.json` exists and identifies training rows from F1/F2, but its probabilities are uncalibrated. This conflicts with older reports/memos that state the artifact is absent. The 900 Phase 5 benchmark output files also exist, but saved per-run outputs do not include persisted ML predictions/observations; their provenance and relationship to the later NO-GO memo must be reconciled before using them as a locked evaluation. No ML performance claim should be derived from those files as currently saved.
* **Documentation consistency:** the Phase 4 audit identified a stale Phase 1.3 report relative to its JSON result. Reconcile this along with the Phase 5 artifact/output provenance before publication tables are assembled.

The above are reported artifact facts; their interpretation as limited evidence is the assessment. Detailed source artifacts include `reports/experiments/finite_shot_distribution_calibration_diagnostic.md`, `finite_shot_distribution_calibration_followup.md`, `independent_generalization_phase2/REPORT.md`, `phase4_diagnosis_reliability_audit/REPORT.md`, and the Phase 5 reports and result directories.

## Candidate contribution assessment

| Direction | Problem and potentially distinct method | Necessary baselines and measurable hypothesis | Main failure modes | Evidence now / decision |
|---|---|---|---|---|
| 1. Separate finite-shot fluctuation from program fault and hardware anomaly | Estimate whether observed output is anomalous under a specified finite-shot null, then separately attribute cause using causal/evidence features. The distinction must be more than an anomaly threshold: use calibrated multinomial/permutation evidence plus cause-specific evidence and matched/overlapping controls. | Unchanged TVD and permutation; Pearson/G-test with small-cell-safe Monte Carlo calibration; where assumptions permit, exact multinomial or two-sample test; simulator's known-truth labels. Hypothesis: at fixed false-positive rate, improve sensitivity or lower shot cost on held-out families without inflating cause misclassification. | Model misspecification, sparse outcomes, data reuse, detector/cause conflation, synthetic noise mismatch. | Calibration demonstrates the problem, not its solution. | 2. Evidence-aware diagnosis with principled abstention | Return “anomaly / no anomaly” and cause/location only when calibrated evidence supports each decision; otherwise abstain. A defensible distinction would calibrate selective risk or guarantee coverage/error targets, not merely use confidence < .60. | Rule diagnosis, ML adapter, and best calibrated statistical baseline; compare coverage-risk curves and selective error at frozen coverage/false-alarm operating points. Hypothesis: lower wrong-cause and wrong-location risk at matched coverage, with calibrated intervals. | Abstention can trivially improve accuracy by refusing most cases; poor calibration; hidden costs; category definitions may overlap. | Phase 2 already records abstentions and not-justified localizations, but no calibrated selective risk contract. Strongest candidate contribution when joined to (1) and localization. |
| 3. Joint fault classification and qubit/gate/source localization | Separate fault detection, cause class, and target localization while propagating evidence and uncertainty across stages. | Li et al. diagnosis/fault-dictionary baseline; project rule localizer; MBFL where source-mutant mappings exist; random/prior localization. Report class and top-k localization, abstention and joint exact success. Hypothesis: improved joint correct-and-supported diagnosis on unseen families. | “Joint” may be only a pipeline; target sets and ground truth may be ambiguous; simulator source localization is not physical fault localization. | Phase 1/2 show a pipeline and testable failures, but fault diagnosis and localization are already established. Treat as an outcome of selective diagnosis, not independent novelty. |
| 4. Generalization across unseen circuit families and fault strengths | Test whether detector thresholds/evidence transfer to structurally unseen circuits, seeds, strengths, and controls. | Grouped family-held-out split, leave-family-out only as development; literature baselines and frozen model; include strength interpolation/extrapolation. Hypothesis: prespecified operating points hold on unseen families and an independent seed range. | Leakage through shared templates, source snippets, seeds, or tuning; tiny family count; simulated-only validity. | Phase 2 is preliminary evidence across six families, with misses concentrated in one family. A rigorous test is essential, but generalization alone is an evaluation requirement rather than methodological novelty. |
| 5. Resource-aware diagnosis | Allocate shots/compute based on uncertainty and the decision's value; report expected cost at fixed risk. | Fixed shot grids (256/1024/4096), sequential test / stopping baseline, unchanged detectors; measure circuits, shots, wall time, memory and risk-cost curves. Hypothesis: achieve a frozen error target with fewer shots without worsening abstention or localization. | Cost depends on backend and batching; stopping bias; latency variance; an adaptive policy selected on test data. | Existing shot grid supports retrospective cost plots but no adaptive budget policy. Resource awareness is valuable as a secondary metric; not novel by itself and should not enlarge the primary paper unless an adaptive policy is developed and independently tested. |

**Combination recommendation:** combine (1), (2), and the decision stages of (3) as one selective, evidence-calibrated diagnostic contribution; require (4) as the evaluation design. Track (5) as a secondary cost curve, not a separate novelty claim. Do not center the paper on a q95 shot-aware TVD cutoff, generic ML classifier, “first” joint diagnosis/localization, or accuracy alone.

## Proposed publication-grade evaluation

### Primary estimand and frozen decision contract

The primary comparison should be the probability of **supported selective diagnosis success**: among all eligible cases, the system either (a) gives the correct cause and target with prespecified evidence support, or (b) abstains; wrong confident causes/targets count as errors, and abstention is reported separately. This outcome must be accompanied by anomaly sensitivity and false-positive rate. Report both unconditional rates and coverage-conditional risk so abstention cannot hide failures.

Before held-out outputs are generated, freeze in a timestamped, hashed preregistration:

1. Primary hypothesis: at the same negative-control false-positive ceiling, evidence-calibrated selective diagnosis improves joint correct-and-supported diagnosis versus the unchanged TVD and permutation pipelines at a nontrivial prespecified coverage floor.
2. Secondary hypothesis: it maintains the operating point across unseen families and fault strengths; its risk-coverage curve is better than confidence-threshold abstention in the current ML adapter.
3. Frozen family/seed/template identities, generated configuration hashes, simulator and dependency versions, random seeds, exclusions, stopping rule, and code commit hash.
4. No tuning against held-out labels. Any candidate threshold/model must be selected only on development families, then serialized and hashed before reveal of held-out results.

### Splitting, metrics, uncertainty, and leakage controls

* Split by **circuit family and template identity first**, then seed; ensure no family/template, generated circuit skeleton, source snippet, or seed appears in any calibration/validation or prior phase and the new held-out set. A new seed on a familiar template is not a family-held-out test. Maintain a machine-checkable overlap assertion and publish split manifests/hashes.
* Stratify held-out cases by control type, fault source/cause, strength (including subtle values), circuit family, and shots. Include negative controls, matched-distribution fault pairs, overlapping causes, and cases where output-only evidence cannot identify cause. Ground truth should be reviewed independently of predictions.
* Report sensitivity/recall, false-positive rate, specificity, precision, abstention, coverage, selective risk, class confusion, joint cause-and-target exact match, top-k localization, and calibration of any confidence/p-value. Precision depends on prevalence; report observed study prevalence and a prevalence-standardized value or avoid general-population interpretation.
* Use exact Clopper–Pearson one-sided binomial bounds for prespecified sensitivity/FPR constraints; use two-sided intervals for descriptive rates. For family-level dependence, supplement per-case binomial intervals with family-cluster bootstrap or exact family-level summaries. State that case-level intervals assume independent Bernoulli outcomes and are optimistic if cases cluster by family.
* Control multiplicity for multiple primary strata or declare one primary endpoint; do not pick the best shot-count subgroup after observing outcomes. For multinomial sparse bins, calibrate the goodness-of-fit statistic under the finite-shot null by Monte Carlo rather than relying on asymptotic chi-square without checking expected counts.
* Report abstentions as a separate outcome and include coverage-risk curves. For matched comparisons, use identical records/shots and paired analysis. Record detector runtime separately from circuit execution time.

### Resource estimate and operational gate

The planning floor above is 1,000 configurations. At 256, 1,024, or 4,096 shots per configuration, that is 256,000 / 1,024,000 / 4,096,000 shot-circuit executions per detector-independent record set. For three primary detectors with shared raw samples, quantum sampling need only occur once per configuration if each detector consumes the same saved counts; without shared records it could be up to 3,000, 768,000 / 3,072,000 / 12,288,000 executions. These are arithmetic planning totals, not a runtime prediction.

An outcome vector with 16 states requires only 128 bytes as 64-bit counts; storing all three shot-level count vectors for 1,000 cases is roughly 0.4 MB before JSON/metadata overhead. Raw per-shot bitstrings are much larger and unnecessary for these distributional detectors. Runtime cannot be responsibly estimated from current artifacts because the prior Windows `RuntimeError: can't allocate lock` and OneDrive manifest contention make parallel behavior/storage latency unreliable, and no valid per-configuration throughput benchmark is authorized here. Before any execution, use safe resume with atomic per-configuration writes, one manifest writer or local non-OneDrive staging, bounded worker count, lock-allocation preflight, disk-space check, and a small separately approved pilot. Pilot timing must then set the runtime estimate. Do not launch until these operational controls are implemented and focused preflight checks pass.

## Claims not currently supported

Do not claim that the project has a statistically valid shot-aware detector; the q95 candidate is exploratory and loses substantial subtle-fault sensitivity at low shots. Do not claim calibrated confidence or principled abstention from a fixed 0.60 cutoff. Do not claim general diagnosis/localization superiority, real-hardware performance, realistic hardware noise, robust external generalization, source-level localization accuracy on an independent corpus, or deployed ML accuracy from the current model artifact. Do not claim all calibration targets passed (30/60 passed). Do not use the QMutBench pilot or empty Bugs4Q report as benchmark evidence. Do not claim “first” joint classification/localization or novelty based only on component combination.

## Go / no-go

**No-go for a novelty claim or another confirmatory run with the current proposed q95 shot-aware TVD rule.** Its existing validation sensitivity at lower shot budgets is inadequate, its cutoff is selected from closely related data, and both statistical testing and quantum diagnosis/localization have close prior art.

**Conditional go for a narrower research program:** develop an evidence-calibrated, selective diagnosis protocol that separates anomaly detection from cause and target claims, and quantify its risk/coverage/cost on strictly unseen circuit families. This becomes publication-worthy only if provenance is reconciled, a defensible statistical null is selected, the preregistered gates are approved before any held-out outputs are examined, and the method beats or meaningfully complements the closest diagnosis and testing baselines. If it does not improve supported diagnosis at matched false-positive rate and coverage, the contribution should be reframed as a negative result/benchmark study or stopped.

## Unresolved decisions before preregistration

1. Choose the primary unit and target population: simulator-generated circuit instances versus source-level program faults; do not mix them into one estimand.
2. Specify whether “hardware anomaly” means a modeled simulator intervention or a real backend event. The current evidence supports only the former.
3. Approve scientifically justified FPR, sensitivity, coverage, and localization gates and conduct power analysis using family-level variability; the suggested numeric gates above are planning proposals.
4. Verify exact 2026 sequential-verification paper metadata and dataset accessibility/licensing before inclusion as a formal baseline.
5. Reconcile Phase 5 model artifact, 900 output files, run provenance, and stale reports; determine whether any held-out family was used in model or rule selection.
6. Determine whether implementable code and assumptions for Li et al. and mutation-based localization are sufficiently comparable; if not, report why and include the closest faithful proxy without implying equivalence.
