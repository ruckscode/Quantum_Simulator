# Adversarial review: finite-shot null-confirmation authorization gate

**Scope:** Static call-graph and trust-boundary review plus the existing focused tests. No confirmation samples were generated; no sampling function was called as part of this review.

## Decision

**BLOCK EXTERNAL TRUST PROVISIONING.** The signature check is cryptographically sound for the parsed approval payload when the trusted public key is genuinely protected. However, the current code does not enforce that trust premise, does not ensure the verified files are the code objects actually executing, and leaves direct sampler entry points outside the authorization gate. Do not install a production reviewer key or use the gate as an authorization boundary until the blockers below are corrected. This decision does not authorize or imply an experiment run.

## Findings by attack case

| Status | Case and evidence | Impact | Smallest correction |
|---|---|---|---|
| **BLOCKER** | **Trust-anchor substitution.** The production paths are fixed constants in `experiments/finite_shot_null_confirmation.py:40–44`, and the CLI exposes no trust-path override (`:434–445`). But ACL protection is only a comment/documented operator step (`:40–42`; trust-gate report lines 7–14). The verifier reads the public key from that path and trusts `reviewer_id` plus `reviewer_independence_verified: true` (`:206–218`); it never checks the directory/file ACL or execution identity. | If the execution identity can write the directory, it can replace the public key and approval with its own keypair and self-asserted identity/independence. Fixed path alone does not make the trust root immutable. The trust files are currently absent, so this is an external precondition, not a demonstrated active key. | Add an enforceable deployment trust check (or a separately trusted launcher that verifies an administrator-owned, non-writable trust root), and provision key files only after verifying effective ACLs and the reviewer identity outside the execution account. Until that exists, stay fail-closed. |
| **PASS, with boundary caveat** | **Manifest substitution through supported CLI/API arguments.** `execute_confirmation` accepts preregistration, binding, and output paths only if their resolved paths equal the fixed constants (`:347–368`); it has no expected-hash or manifest parameters. `artifact_manifest` recomputes hashes and runtime data (`:169–193`), and approval equality is exact (`:231–232`). | A normal CLI caller cannot submit a replacement expected manifest or hashes. `verify_signed_approval` itself has optional path parameters (`:200–204`), but the execution path passes the fixed trust constants. This protects only that entry point; Python code in the same process can mutate module globals or call other functions. | Keep authorization checks in a minimal, independently protected launcher and do not treat callable Python helpers as an isolation boundary. |
| **BLOCKER** | **Incomplete coverage of code actually imported/executed.** The driver imports `numpy`, `cryptography`, and `pair_outcome` at module import time (`:20–32`). `pair_outcome` in turn imports `compare_distributions` at runner import time (`experiments/finite_shot_synthetic_characterization.py:13–16, 52–56`). The manifest hashes the driver, reference-runner file, stats file, `pyproject.toml`, configuration, and seed ledger, and records Python/NumPy/cryptography version strings plus a generic bit-generator name (`finite_shot_null_confirmation.py:169–193`). It does not verify the origin or loaded code identity of `pair_outcome` or `compare_distributions`, hash the Python/NumPy/cryptography binaries, or bind the interpreter build, import path, startup hooks, or effective environment. | A shadowed module, prepopulated `sys.modules`, import hook, or modified runtime can provide different in-memory behavior while the manifest hashes the expected on-disk files. Version strings do not prove package contents. This undermines the principal artifact-to-execution claim. | Launch in a controlled, isolated runtime from an immutable installation; verify module origins and package/runtime digests against the signed manifest before loading executable modules. Bind the exact interpreter and dependency artifacts, not version strings alone. |
| **BLOCKER** | **Path, symlink, and time-of-check/time-of-use substitution.** `execute_confirmation` calls `.resolve()` on both the caller path and the same mutable module constant (`:357–359`), so this does not establish that the target is a regular, non-symlink file beneath a trusted root. It reads preregistration and binding (`:362–363`), then reopens/hashes files in `verify_hash_bindings` (`:148–165`) and again in `artifact_manifest` (`:178–185`). Imported code has already been loaded before these checks (`:20–32`). | A writable checkout permits source/path changes between import, JSON reads, digest checks, and sampling. In particular, a process can have one driver/helper loaded while the on-disk path later presents different bytes to the approval check. There is no immutable file handle or single-read verified snapshot tying approved bytes to loaded code. | Use a trusted bootstrap to verify immutable staged files before importing them; reject symlinks/reparse points and paths outside the protected stage; retain and execute from the verified snapshot. Avoid separate uncoordinated reads for parse and hash. |
| **UNRESOLVED** | **Approval replay.** Artifact hashes, configuration, runtime identifiers, and seed-ledger digest make an approval for a different artifact version stale (`:174–193, 231–232`). The approval has no expiration, unique run nonce, or consumed-approval ledger. Output is create-only (`:360–361, 428–430`), but the existence check is not a lock and the output can be removed; concurrent invocations can both pass the initial check. | Replaying approval for the exact same manifest is accepted. The deterministic seed ledger means a rerun repeats the same pseudo-random streams; such a retry is not a new independent confirmation sample. The result path prevents ordinary overwrite, but it does not prove a single execution or prevent duplicate attempts. | Bind a unique execution authorization to a durable, externally protected one-time run record and atomically consume it before sampling. Record aborted attempts and prohibit pooling/relabeling repeated-seed reruns as new replicates. |
| **BLOCKER / UNRESOLVED** | **Signature and reviewer identity.** The verifier signs/verifies canonical JSON of all parsed approval fields except `signature_base64`, checks Ed25519 against the trusted key, checks the key fingerprint, and matches the key record's reviewer ID (`:215–242`). That is a valid cryptographic signature check assuming the key record is authentic. However, standard `json.loads` is used without duplicate-key rejection (`:207–208`), so different raw JSON texts with duplicate keys can parse to the same signed mapping; `independence_basis` and `review_scope` are only nonempty/content-presence checks (`:221–230`). The Boolean independence field and reviewer ID are assertions in the trust file, not proof of a real person's identity or independence (`:216–218`). | Cryptographic validity is not equivalent to verified human identity or independent review. Duplicate-key JSON is semantically ambiguous to other parsers/auditors, even though this Python verifier signs the last-value mapping. The test key proves only the implementation mechanics. | Reject duplicate JSON keys and require a strict schema/canonical encoding. Provision the key-to-person identity and independence through a documented external custodian process; record that evidence outside the caller-writable workspace. |
| **PASS for missing/malformed material; BLOCKER for trust-root integrity** | **Fail-closed behavior.** Missing/unreadable files and JSON parse errors are converted to `ValueError` (`:206–210`); type, schema, status, manifest, key-ID, and signature mismatches also raise before the sampling loop (`:211–242, 362–368`). Runtime mismatches likewise raise before sampling (`:369–371`). | No missing or malformed trust material was found to fall through to sampling in the inspected path. But fail-closed parsing does not protect a replaced trust anchor or imported code that differs from hashed files. | Preserve current fail-closed checks and close the trust-anchor and code-loading blockers above. |
| **BLOCKER** | **Execution bypass through helper entry points.** The confirmation loop invokes the module-global imported `pair_outcome` directly (`finite_shot_null_confirmation.py:394–408`). The helper itself generates both multinomial count vectors without authorization checks (`experiments/finite_shot_synthetic_characterization.py:52–56`), and its general runner calls it directly (`:124–149`). Tests also call `pair_outcome` directly (`tests/test_finite_shot_synthetic_characterization.py:35–36`). `execute_confirmation`'s flag/signature gate applies only to that function and `main` (`finite_shot_null_confirmation.py:347–368, 434–450`). | Any caller able to import the project can generate the same kind of confirmation draws or invoke the helper with the confirmation condition/seeds without passing the Ed25519 gate. Python-level callers can also monkeypatch globals before calling the driver. The gate controls the official driver path, not sample generation by the execution identity. | If the authorization is intended to control whether samples may be generated, move sampling behind a single protected executable/service that owns the RNG and data path, and prevent the execution identity from invoking alternate runners/helpers. Otherwise explicitly narrow the claim to protecting only the official result-writing entry point. |
| **UNRESOLVED** | **Partial execution and recovery.** The loop records only aggregate flags in memory and writes the result after all registered pairs (`:392–431`); there is no partial checkpoint, attempt ID, or durable consumed-approval record. A failure before final write leaves no result; rerunning recreates the same ledger and seeds (`:270–303`). | Restarting is reproducible but reuses every deterministic seed stream. It does not create a fresh independent replicate set. Without attempt records, operators could confuse a retry with an independent second run or combine duplicate outputs. Within a single uninterrupted run, the 76,456 seeds are checked unique and non-overlapping with prior streams. | Record and externally protect attempt state, mark interrupted attempts, and make clear that restart repeats the same registered dataset. Do not pool retries; use a new preregistered seed condition only for a genuinely new confirmation. |

## Tests and lightweight checks

Ran `.venv\Scripts\python.exe -m pytest tests/test_finite_shot_null_confirmation.py -q --tb=short --basetemp .pytest-finite-shot-adversarial-20261015-a`: **8 passed**. These tests exercise signature acceptance against a test key, stale/tampered manifest rejection, pending-review rejection before the monkeypatched sampler, fixed workload/boundary, and deterministic seed-ledger derivation. They do not test OS ACLs, imports shadowed through `sys.modules`/`sys.path`, symlink/TOCTOU races, duplicate JSON keys, one-time replay, or direct sampler bypass. No test ran the confirmation workload.

## Required corrections before external trust provisioning

1. Put execution behind a protected bootstrap/launcher that verifies immutable artifacts before import and runs only the verified code/dependencies in a controlled environment.
2. Enforce the trust-root ACL and reviewer identity mapping as a deployment check, not solely as prose or a mutable `reviewer_independence_verified` field.
3. Reject duplicate-key/noncanonical approval JSON and establish an external one-time authorization/attempt ledger if approvals are intended to authorize a single run.
4. Either gate every route that can generate confirmation samples or narrow and document the gate's scope to the official result-writing driver; the current public helper and original runner remain callable.

The fixed scientific design was not changed. The current production trust files remain absent. No reviewer identity or independence was verified in this review, and no approval was created.
